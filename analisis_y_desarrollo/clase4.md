# Síntesis: Historias de Usuario y Documentación de Requerimientos en Metodologías Ágiles

## 1. Concepto de Historia de Usuario

Las Historias de Usuario son una técnica utilizada en metodologías ágiles para describir funcionalidades desde la perspectiva de quien utilizará el sistema. Se redactan de forma sencilla y comprensible, priorizando el beneficio que recibirá el usuario antes que los detalles técnicos de implementación.

### Formato habitual

Como [rol o tipo de usuario]
Quiero [funcionalidad o acción que desea realizar]
Para [beneficio o propósito que obtiene]

### Ejemplo

*"Como usuario de una aplicación bancaria, quiero visualizar el saldo de mi cuenta al ingresar al sistema para conocer de inmediato los fondos disponibles."*

---

## 2. Principios INVEST para evaluar Historias de Usuario

Una Historia de Usuario de calidad debe cumplir con los criterios INVEST, los cuales ayudan a garantizar que sea útil para el desarrollo y la gestión del proyecto.

### I – Independiente

La historia debe poder desarrollarse sin depender obligatoriamente de otras funcionalidades.

### N – Negociable

Su contenido puede discutirse y ajustarse durante el proyecto; no representa una especificación inalterable.

### V – Valiosa

Debe generar un beneficio concreto para el usuario o aportar valor al negocio.

### E – Estimable

El equipo debe ser capaz de estimar razonablemente el esfuerzo requerido para implementarla.

### S – Pequeña

Debe tener un alcance reducido que permita completarla dentro de un sprint o iteración.

### T – Verificable

Su cumplimiento debe poder comprobarse mediante pruebas o validaciones objetivas.

---

## 3. Criterios de Aceptación

Los criterios de aceptación establecen las condiciones que una funcionalidad debe cumplir para ser considerada terminada y aceptada por el cliente.

### Estructura recomendada

**Dado (Given):** situación o contexto inicial.
**Cuando (When):** acción realizada por el usuario.
**Entonces (Then):** resultado esperado del sistema.

### Ejemplo

**Dado** que el usuario ha iniciado sesión correctamente,
**Cuando** accede a la pantalla principal,
**Entonces** debe visualizar el saldo actualizado de su cuenta.

---

## 4. Diferencias entre Historias de Usuario y Casos de Uso

### Historias de Usuario

* Se enfocan en el valor entregado al usuario.
* Utilizan descripciones breves y fáciles de comprender.
* Favorecen la comunicación entre clientes y equipos ágiles.
* Incluyen criterios de aceptación para validar el resultado.

### Casos de Uso

* Describen detalladamente el comportamiento del sistema.
* Documentan flujos principales, alternativos y excepciones.
* Poseen un nivel de detalle técnico mayor.
* Son comunes en metodologías tradicionales y modelos UML.

---

## 5. Actividades Prácticas del Módulo

Durante el desarrollo del tema se realizaron ejercicios orientados a fortalecer la comprensión de las Historias de Usuario y los criterios INVEST.

Entre las actividades más destacadas se encuentran:

* Analizar historias para determinar si cumplen o no con los principios INVEST.
* Identificar correctamente los elementos de la estructura “Como – Quiero – Para”.
* Evaluar criterios de aceptación y escenarios de prueba.
* Reconocer historias demasiado amplias, poco claras o que no generan valor para el usuario.
* Resolver preguntas de validación mediante ejercicios de selección y verdadero/falso.

Estas actividades permiten desarrollar la capacidad de redactar requerimientos ágiles claros, medibles y alineados con las necesidades del negocio.
