# Requerimientos del Software 

Este fue diseñado para principalmente enseñar a capturar, escribir y trabajar los requerimientos de manera profesional. Esto sirve como el puente esencial de una idea al código.

## Definición y Fundamentos
Este es una propiedad documentada que un sistema debe de poseer para la resolución de problemas, ya que esto vendría siendo una declaración verificable de una funcionalidad o restricción.

Estos se mueven en niveles diferentes de abstracción, desde la necesidad informal de un usuario e incluso la especificación técnica detallada y para que este sea considerado de calidad debe de cumplir unas características:
 
1. Ser necesario.
2. No ambiguo.
3. Verificable. 
4. Consistente.
5. ompleto. 
6. Anatómico.
7. Transable.

## Requerimientos Funcionales

Estos nos sirven para describir el “Qué hace” un sistema. Acciones concretas, tareas o los cálculos que debe de realizar.

La identificación se reconoce por el uso de verbos de acción y la definición de las entradas y las salidas y la plantilla profesional que recomienda seguir una acción con condiciones o restricciones.

En sus categorías incluyen autenticación, cálculos, persistencia de datos, comunicación, reportes y validación.

## Requerimientos no Funcionales

Este describe el “comportamiento” del sistema no qué hace. Este define caracteres de calidad, restricciones y propiedades que el sistema debe de seguir.

Su importancia viene de que puede cumplir todos sus RF pero fracasa si este es lento, inseguro o difícil para su uso.

## Historias del Usuario

Esta es la forma rápida de capturar requerimientos desde  la perspectiva del usuario. Se usa la fórmula de: como [tipo de usuario], quiero [acción/funcionalidad], para [objetivo/beneficio].
